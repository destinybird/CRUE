## 执行摘要

本文档完整说明研究工作中训练语料与评测语料的数据预处理过程，包括数据来源、清洗规则、过滤判据、质量控制机制、数据隔离策略以及数据的留存与可复现性状况。文档面向需要复核本研究数据工程细节的读者，所有数字均直接取自留存的原始文件与代码输出，关键环节给出了可直接重跑的复现代码与预期校验值。

本研究的数据预处理不是单一的一次性操作，而是一条**五级递进过滤链**，每一级针对不同粒度的缺陷设置确定性判据：

**表 0-1  五级递进过滤链总览**

| 层级 | 过滤粒度 | 核心判据 | 输入 | 输出 | 留存率 |
| --- | --- | --- | --- | --- | --- |
| L0 | 原始标注记录 | 9 项标注字段完整性校验 | 7,048 | 7,032 | 99.77% |
| L1 | 结节 | 多标注者评分共识去重（均值） | 7,032 | 6,389 | 90.86% |
| L2 | 影像表型组合 | 特征指纹同组上限 3 条 | 6,389 | 3,816 | 59.72% |
| L3 | 标签分布 | 恶性度分层配额（每级 ≤500） | 3,816 | 2,424 | 63.52% |
| L4 | 生成语料 | 六维硬约束质检（任一 ERROR 即剔除） | 7,272 | 5,854 / 6,981 | 80.5% / 96.0% |
| L5 | 生成语料 | 大模型语义审核（4 维均 >4 分） | 5,854 / 6,981 | 4,566 / 6,546 | 78.0% / 93.8% |

L4 与 L5 两级分别对应多轮对话场景与单轮病历场景（顺序为「多轮 / 单轮」）。经全部五级过滤后，阶段性的数据规模变化为：**7,048 条原始标注 → 2,424 个建模结节 → 7,272 条生成语料 → 7,269 条最终训练语料**；评测侧则为 **1,287 条候选样本 → 722 条纯净样本**，并展开为 **4,411 个多轮评测轮次**。

### 本文档的三个要点

- **清洗链路完全可复现。** 从 7,048 到 2,424 的五步过滤已用留存的中间文件实际重跑验证，五步数字与恶性度分布逐级精确命中。这意味着清洗结果不依赖任何未记录的人工判断。

## 1　文档目的与处理架构

### 1.1　文档目的与范围

本研究的任务是为肺结节临床辅助诊疗场景构建高质量的中文训练语料与评测语料。该任务面临一个结构性困难：真实医患对话数据受患者隐私保护限制而无法获取，而人工标注医疗对话数据所需的时间成本与专业资质成本均难以承受。因此本研究采用「公开影像标注 + 权威临床指南 + 大模型合成」的技术路线，以 LIDC-IDRI 数据集中放射科医师的结构化标注作为**事实基础**，以 Fleischner 指南、NCCN 指南与中国肺结节诊治指南中的条款作为**逻辑约束**，驱动大语言模型合成结构化病历报告与多轮医患对话。

在这一技术路线下，数据预处理承担的任务远不止「去重、去空、去异常」这类常规清洗。由于数据的后半段由生成模型产出，预处理必须同时解决两类性质不同的问题：**上游的标注数据如何转化为可直接驱动规则匹配的确定性结构化特征**，以及**下游的生成文本如何被确定性判据筛选到可安全用于监督微调的质量水位**。本文档即围绕这两条主线组织。

本文档覆盖的数据范围如下：

- **影像标注数据**：LIDC-IDRI 的结构化结节标注记录，7,048 条原始记录，13 个字段。
- **规则知识库**：结构化循证医学规则表，131 条规则，10 个类别。
- **生成语料**：由上述两者驱动的单轮病历报告与多轮医患对话，7,272 条原始产出。
- **训练语料**：经全部质检后合并去重的监督微调训练集，7,269 条。
- **评测语料**：独立构建的单轮与多轮评测集，722 条样本 / 4,411 个评测轮次。

本文档不覆盖模型训练过程（监督微调与强化学习的超参数配置）与模型推理服务的部署细节，这两部分属于系统实现范畴，仅在需要说明数据流向时简要提及。

### 1.2　数据处理总体架构

数据从原始标注到可用训练语料，经历七个顺序执行的处理阶段。前四阶段作用于影像标注数据，属于「确定性数据处理」；第五、六阶段作用于生成文本，属于「生成质量控制」；第七阶段构建评测集并检查数据隔离。七个阶段之间通过结构化的 JSON 中间表示传递数据，每阶段的输出均可独立检查。

**表 1-1  数据处理七阶段架构**

| 阶段 | 名称 | 处理性质 | 核心动作 | 主要产出 |
| --- | --- | --- | --- | --- |
| ① | 记录级清洗 | 确定性 | 字段完整性校验，剔除标注缺失记录 | 7,032 条记录 |
| ② | 结节级去重 | 确定性 | 多标注者评分取均值，排除观察者间差异 | 6,389 个结节 |
| ③ | 表型去重与配平 | 确定性 | 特征指纹去重 + 恶性度分层配额 | 2,424 个结节 |
| ④ | 特征标准化 | 确定性 | 数值 → 临床术语映射 + 类别归并 | 临床可读特征向量 |
| ⑤ | 生成端硬闸 | 生成控制 | 解码约束、解析回退、失败重跑 | 7,272 条原始语料 |
| ⑥ | 双阶段质检 | 确定性 + 语义 | 六维硬约束过滤 + 大模型语义审核 | 7,269 条训练语料 |
| ⑦ | 评测集构建 | 确定性 | 纯净子集筛选、单轮/多轮展开、隔离检查 | 722 样本 / 4,411 轮次 |

这一架构的核心设计取舍在于**把不确定性尽可能前置并收敛**。阶段①至④全部是确定性的：给定同一份原始 CSV，输出必然完全一致，这保证了规则匹配阶段面对的输入是稳定且可审计的。阶段⑤引入了生成模型，是整条链路中唯一的不确定性来源；阶段⑥随即用确定性判据把这份不确定性重新约束回可控范围。换言之，生成模型只被允许在「已被规则收窄的空间」内产生文本，而其产出的文本必须通过完全独立的确定性检验才能进入训练集。

## 2　数据来源与合规性

### 2.1　影像标注数据源：LIDC-IDRI

本研究的影像事实基础来自 **LIDC-IDRI**（Lung Image Database Consortium and Image Database Resource Initiative）。该数据集由美国国家癌症研究所（NCI）下属的肿瘤影像计划资助建设，收录了 1,018 例患者的胸部 CT 扫描序列，并由多位放射科医师对每个结节独立完成标注。其标注内容包含结节的位置几何参数、密度特征、形态学评分与恶性可能性评估，是国际上肺结节研究使用最广泛的公开参考数据库。

LIDC-IDRI 的原始标注以 XML 文件形式随 DICOM 影像一同提供，每个 XML 对应一次阅片会话（reading session），由最多 4 位放射科医师各自独立完成。本研究使用的结构化标注 CSV 是从这些 XML 中提取并整理得到的扁平表，共 7,048 行、13 个字段：

**表 2-1  结构化标注表的字段口径（13 个字段）**

| 字段名 | 数据类型 | 取值范围 | 含义 |
| --- | --- | --- | --- |
| xml_file | 字符串 | — | 来源标注 XML 文件名，用于追溯原始记录 |
| patient_folder | 整数 | — | 患者文件夹编号（LIDC 去标识编号） |
| nodule_id | 整数 | — | 结节在所属标注文件内的编号 |
| malignancy | 整数 | 1–5 | 放射科医师对结节恶性可能性的专家评分，5 为极可能恶性 |
| texture | 整数 | 1–5 | 纹理评分，表征结节内部 CT 密度表现，用于推断密度类型 |
| subtlety | 整数 | 1–5 | 精细度评分，表征结节在影像上的视觉显著程度 |
| internalStructure | 整数 | 1–4 | 内部结构评分（软组织 / 液性 / 脂肪 / 气体密度） |
| calcification | 整数 | 1–6 | 钙化类型评分，6 表示无钙化 |
| sphericity | 整数 | 1/3/5 | 球形度评分，1 线状、3 卵圆形、5 圆形 |
| margin | 整数 | 1–5 | 边缘特征评分，1 模糊、5 清晰 |
| lobulation | 整数 | 1–5 | 分叶征评分，5 为明显分叶 |
| spiculation | 整数 | 1–5 | 毛刺征评分，5 为明显毛刺 |
| diameter_pixels | 浮点数 | 实数 | 结节最大径的像素测量值，需换算为毫米 |

> **【说明】**上表中除 xml_file、patient_folder、nodule_id、diameter_pixels 外的 9 个字段，均代表**某一位放射科医师的一次独立评分**。同一结节若被 4 位医师分别阅片，就会在表中产生 4 行记录。这正是阶段②必须做共识去重的原因——在把标注当作「事实依据」使用之前，必须先消除观察者间差异。

### 2.2　循证医学规则来源

本研究的规则知识库（131 条结构化规则）主要编制自三份权威临床指南。这三份指南共同界定了「什么样的结节应匹配什么样的随访或处置建议」，是规则匹配阶段的医学知识基底，也是生成阶段提示词中「规则依据文本」字段的直接来源。

**表 2-2  规则库编制的指南来源**

| 指南 | 发布机构与版本 | 在本文中的作用 |
| --- | --- | --- |
| Fleischner 学会偶发性肺结节管理指南 | Fleischner Society，2017 年版，发表于 Radiology 2017;284(1):228–243 | 提供结节大小 × 密度类型 → 随访间隔的核心决策矩阵，是规则库中结节管理类规则的主要依据 |
| NSCLC 临床实践指南 | NCCN，Version 4.2024 | 提供从初始评估、分期、检查、治疗到术后随访的完整临床路径规则 |
| 中国肺部结节分类、诊断与治疗指南 | 中华医学会呼吸病学分会，2016 年版 | 在中国人群流行病学与临床实践习惯基础上对国际指南作本土化调适，补充诊断路径与管理策略 |

三份指南的完整出处与访问链接在文末的资源清单中逐条列出。需要强调的是，规则库中每条规则都保留了「IF 条件 → THEN 结论」的原文表述与出处标识，这一设计在后文阶段⑤中起到关键作用：生成模型被要求逐字引用匹配到的规则条款，使生成文本的临床结论具备可追溯的依据，而不是依赖模型参数中模糊的医学记忆。

### 2.3　数据合规与伦理

本研究的数据使用在合规性上有明确边界，可分三点说明：

- **影像数据为公开去标识数据。** LIDC-IDRI 在 TCIA 平台上以公开研究用途发布，所有患者标识已按 HIPAA 要求去标识化处理，不含任何可回溯到个体的信息。使用该数据集不涉及额外的伦理审批或知情同意流程。
- **不存在真实患者对话数据。** 本研究中的全部医患对话文本均为合成数据，由大语言模型在「影像标注事实 + 指南规则约束」的条件下生成，不采集、不使用、不推断任何真实患者的问诊记录。合成患者档案（姓名以外的年龄、性别、吸烟史等）由模型随机配置，与 LIDC 中的任何真实个体无对应关系。
- **合成数据的性质已在论文中明确声明。** 生成语料被定位为「训练用合成语料」而非「临床数据」，模型评估结论仅反映其在合成语料分布上的表现，不构成任何临床有效性或医疗器械效能的证据。本文档所述的数据工程结论同样受此边界约束。

> **【合规提示】**在对合成语料做任何二次使用（如公开发布、迁移到其他任务）时，必须同时传递「合成非真实」这一属性，避免下游使用者误将其视为真实临床数据。本项目在训练集的每条样本 metadata 中保留了 `source: LIDC-IDRI` 与合成患者编号，以支持来源追溯。

## 3　记录级与结节级清洗

本章与第 4 章描述的是整条链路中最基础、也最需要确定性的部分：把 7,048 条带有观察者间差异的原始标注记录，转化为 2,424 条可直接用于规则匹配的唯一结节记录。这一过程共五步，每一步都有明确的判据与可核验的输出规模。

### 3.1　清洗链路的完整定义

**表 3-1  记录级与结节级清洗的五步定义**

| 步骤 | 操作 | 判据 | 输入 | 输出 | 剔除量 |
| --- | --- | --- | --- | --- | --- |
| S1 | 字段完整性校验 | 9 项标注字段任一为空即剔除 | 7,048 | 7,032 | 16 |
| S2 | 多标注者共识去重 | 按（xml_file, nodule_id）分组，评分取均值后四舍五入 | 7,032 | 6,389 | 643 |
| S3 | 特征指纹统计 | 9 项整数评分按序拼接为指纹；共 2,551 种唯一组合 | 6,389 | — | — |
| S4 | 同质化抑制 | 同一指纹最多保留 3 条 | 6,389 | 3,816 | 2,573 |
| S5 | 恶性度分层配额 | malignancy 每一级最多保留 500 条 | 3,816 | 2,424 | 1,392 |

上述五步的输出规模构成一条完整的漏斗，最终落地的 2,424 条记录即清洗后的建模样本集合。该集合已固化为 `lidc_filtered_balanced.csv`（2,424 行 × 19 列），在原始 13 个字段基础上增加了 6 个派生字段（特征指纹、直径毫米值、大小类别、密度描述、恶性度描述、风险等级），供后续规则匹配与提示词构造直接使用。

### 3.2　S1：字段完整性校验（7,048 → 7,032）

第一步解决的是**标注缺失**问题。LIDC 的标注机制允许放射科医师对某个结节「不予评分」，表现为该结节某一项或多项评分字段为空。这类记录无法支撑后续的密度类型推断、大小分类或风险分层，属于不可修复的结构性缺失，必须整条剔除而非插补。

判据设定为：9 项标注评分字段（malignancy、texture、subtlety、internalStructure、calcification、sphericity、margin、lobulation、spiculation）中**任一字段为空即剔除**。实测 7,048 条原始记录中有 16 条命中，清洗后剩余 **7,032** 条。

> **【口径】口径澄清。** 直径字段 `diameter_pixels` 在本步中不作为剔除条件。该字段实测有 18 条为空，其中 16 条同时伴随评分字段缺失（已在 S1 中剔除），另有 2 条仅直径缺失。本文档保留这 2 条记录，不对直径做插补，而是在下游以「直径缺失」标记传递，其处理方式与影响见第 8.5 节「已知边界情况」。这一取舍的理由是：评分字段承载的是规则匹配的全部决策依据，而直径可由大小维度兜底；两害相权，宁可保留记录并显式标记，也不做无依据的数值插补。

### 3.3　S2：多标注者共识去重（7,032 → 6,389）

第二步解决的是**观察者间差异**问题。同一结节被多位放射科医师独立阅片时，各自给出的评分往往存在 1 分以内的分歧。若把每位医师的评分当作独立样本，会产生两个后果：一是同一结节在训练集中重复出现，导致模型对少数「被反复评分」的结节过拟合；二是同一结节对应的不同评分组合会匹配到不同的规则，使事实基础自相矛盾。

因此本步以 **（xml_file, nodule_id）** 为结节身份键作分组聚合，对 9 项标注评分与直径取算术平均值，再四舍五入回整数区间，从而把「多位医师的多份评分」收敛为「一份临床表现的共识描述」。聚合后唯一结节数由 7,032 降为 **6,389**，即剔除了 643 条重复阅片记录。

四舍五入而非取整或取众数的原因在于：均值能同时利用全部医师的判断信息，避免「某位医师评分偏低就把整体拉低」的极端化；而评分量纲本身是 1–5 的离散等级，四舍五入保证了输出的评分仍落在同一量纲上，不会产生 2.5 这类原始量纲中不存在的等级，从而维持了与规则库阈值判断的相容性。

### 3.4　一致性核验

清洗结果的可信度不取决于流程设计的合理性，而取决于输出能否与独立证据对上。本步做了三重交叉核验：

- **规模一致性**：重跑 S1–S2 得到的唯一结节数为 6,389，与留存清洗报告 `filtering_report.txt` 记载的数字完全一致。
- **分布一致性**：重跑 S3–S5 得到的恶性度分布为 「0 级 2 条、1 级 446 条、2–4 级各 500 条、5 级 476 条」，与 `lidc_filtered_balanced.csv` 中 malignancy 字段的实际计数**逐级精确相同**。
- **结构一致性**：清洗后 CSV 的行数（2,424）与清洗报告记载的最终样本数一致，且派生字段（特征指纹、大小类别、风险等级）无空值异常。

> **【核验结论】**三重核验全部通过，说明清洗链路**不依赖任何未记录在案的隐含步骤或人工干预**。这是后续所有数据工程结论成立的前提，也是第 8 章「可复现性」主张的直接证据。完整复现代码随本文档一并给出，在同一份 CSV 上实测可在秒级完成并对出全部五步数字。

## 4　特征组合去重与标签配平

经过前两步，数据在「记录身份」层面已经干净：每个结节恰好对应一条记录。但「记录唯一」不等于「信息唯一」。本章处理的是两个更隐蔽的数据质量问题：**影像表型的高度同质化**，以及**恶性度标签的严重偏斜**。

### 4.1　S3：特征指纹的构造（6,389 → 2,551 种组合）

LIDC 的 9 项评分均是 1–5（或 1–4、1–6）的小整数，取值空间有限。6,389 个结节分布在这样一个离散空间中，必然出现大量**评分向量完全相同**的结节——它们的影像学表现被描述为同一种表型组合，只是来自不同患者。

本步据此构造**特征指纹**（feature_hash）：把 9 项已整数化的评分按固定字段顺序用下划线拼接为一个字符串，作为该结节的表型标识。例如评分向量（subtlety=3, internalStructure=1, calcification=6, sphericity=3, margin=4, lobulation=1, spiculation=1, texture=5, malignancy=3）对应指纹 `3_1_6_3_4_1_1_5_3`。统计后，6,389 个结节共归入 **2,551 种唯一指纹**，即平均每种表型组合对应约 2.5 个结节。

### 4.2　S4：同质化抑制（6,389 → 3,816）

若不加干预，占比最高的少数几种表型组合会在训练集中占据极高权重。以恶性度 3 分为例，其在 6,389 个结节中有 1,599 条，而恶性度 5 分仅 476 条——模型会学到「几乎所有结节都是中间不确定性」这一错误的先验。更严重的是，同质化会导致生成语料的多样性坍缩：相同表型组合驱动大模型生成的病历在结构、措辞与处置建议上高度雷同，使「合成数据扩增」在实质上失效。

本步的判据是**同一指纹最多保留 3 条**。选择 3 而非更小或更大的阈值，对应的是后续「一对三」的档案合成策略：每个结节合成 3 套差异化患者档案，而每个表型组合最多贡献 3 个结节 → 最多 9 条生成语料。这一阈值把「同一影像表型」在训练集中的最大权重压到可控范围内，同时保留了必要的表型覆盖广度。执行后样本数由 6,389 降为 **3,816**，剔除 2,573 条。

### 4.3　S5：恶性度分层配额（3,816 → 2,424）

最后一步控制**标签分布**。恶性度评分是整个数据集中与临床决策最直接相关的标签，其分布直接决定模型学到什么样的风险判断先验。经过 S4 后分布仍不均衡，因此施加「每一级最多保留 500 条」的分层配额。由于只做上限裁剪、不做下采样补偿，原始数量不足 500 的等级会被完整保留，这就解释了为何最终 1 级的数目是 446 而非 500。

**表 4-1  最终建模样本的恶性度分布（2,424 条）**

| Malignancy 等级 | 临床含义 | S5 后样本数 | 占比 |
| --- | --- | --- | --- |
| 0 | （原始标注中的异常值，见 8.5 节） | 2 | 0.08% |
| 1 | 高度良性 | 446 | 18.40% |
| 2 | 可能良性 | 500 | 20.63% |
| 3 | 不确定 | 500 | 20.63% |
| 4 | 可能恶性 | 500 | 20.63% |
| 5 | 高度恶性 | 476 | 19.64% |

配平后的分布接近均匀，最高与最低有效等级（1 级 446 条 vs 2–4 级 500 条）的差距被压缩到 12% 以内。这一处理对下游有直接影响：模型不会因某一等级样本稀少而在该风险层级上系统性失准，评测中的 Rule F1 也不会被多数类主导。

### 4.5　S6：影像特征的临床术语标准化

至此，数据在统计层面已经可用。但原始标注是整数编码，而下游的提示词构造与文本生成要求的是自然语言临床描述。「边缘评分=3」这样的表达既不符合放射科报告的书写习惯，也无法被语言模型正确理解为「边缘不规则」这一具有诊断含义的征象。因此本步把 7 项形态学评分逐项翻译为标准化临床术语。

**表 4-3  形态学评分到临床术语的映射规则**

| 特征 | 数值范围 | 映射规则 |
| --- | --- | --- |
| 内部结构 | 1–4 | 1→软组织密度，2→液性密度，3→脂肪密度，4→气体密度 |
| 钙化类型 | 1–6 | 1→爆米花样钙化，2→层状钙化，3→实性钙化，4→非中心钙化，5→中心钙化，6→无钙化 |
| 球形度 | 1 / 3 / 5 | 1→线状，3→卵圆形，5→圆形 |
| 边缘特征 | 1–5 | 1→边界模糊 … 5→边界清晰（2–4 按比例线性过渡） |
| 分叶征 | 1–5 | 1→无分叶 … 5→明显分叶（2–4 按比例线性过渡） |
| 毛刺征 | 1–5 | 1→无毛刺 … 5→明显毛刺（2–4 按比例线性过渡） |

映射设计遵循两条原则。**术语规范性**：输出采用放射科报告中的通行措辞，例如把钙化评分 6 译为「无钙化」而非「没有钙化」，以复现规范报告的表达习惯。**语义保真性**：映射不丢失也不扭曲原始编码承载的诊断信息；对于球形度这类仅有三个离散取值的特征采用枚举映射以保持语义边界清晰，对于边缘、分叶、毛刺等具有渐进特性的特征则采用首尾锚定、中间线性过渡的方案。

除逐项翻译外，还需把两项核心评分压缩为具有明确临床管理含义的类别标签，使后续规则匹配能够在与指南条款相同的概念层级上执行，避免因评分边界模糊导致匹配歧义。

**表 4-4  纹理评分与恶性度评分的类别归并**

| 原始字段 | 原始取值 | 归并结果 | 归并依据 |
| --- | --- | --- | --- |
| 纹理评分 texture | 1 或 2 | 磨玻璃密度 | CT 表现为局灶性密度轻度增高，不掩盖其内支气管与血管结构 |
|  | 3 | 部分实性 | 磨玻璃成分与实性成分混合存在 |
|  | 4 或 5 | 实性 | 均匀软组织密度影 |
| 恶性度评分 malignancy | 1 或 2 | 低危 | 对应 Fleischner 指南的低风险分支 |
|  | 3 | 中危 | 对应需短期随访的中间分支 |

> **【设计取舍】**偶发性肺结节指南中的危险度分层通常基于患者行为学背景（如吸烟史、年龄、家族史）。但 LIDC 作为影像公开数据集**不包含患者背景信息**，因此本文直接把放射科医师的影像学恶性共识评分映射为结节的临床风险层级。这一映射使规则匹配得以在无患者背景的条件下执行，其代价是风险分层不含行为学因素；这一局限在第 7.4 节讨论评测口径时再次提及。

### 4.7　恶性概率的数值化估计

生成语料需要给出具体的恶性概率数值，而不仅仅是「低危 / 中高危」这类定性标签。为此本研究建立了一个可解释的 logistic 映射，把离散的专家评分与形态学征象转换为连续的恶性概率百分比：

logit(p) = α × malignancy_score + β + Σ(形态学特征调节项)，p = sigmoid(logit)

**表 4-5  恶性概率 logistic 映射的参数与设定依据**

| 参数 / 调节项 | 取值 | 设定依据 |
| --- | --- | --- |
| α（恶性评分系数） | 1.5 | 使评分 1 → 约 2.4%、3 → 约 33%、5 → 约 91%，与 LIDC 标注语义对齐 |
| β（截距） | −5.2 | 与 α 配合锚定上述三点 |
| 毛刺征阳性（spiculation ≥ 4） | logit + 0.5 | 影像征象效应量参考 Brock / Lung-RADS，在 logit 尺度取保守值 |
| 分叶征阳性（lobulation ≥ 4） | logit + 0.3 | 同上 |
| 良性钙化模式（calcification ∈ 1,2,3） | logit − 0.7 | 钙化是重要的良性指示征象 |
| 形态规则（sphericity ≥ 4） | logit − 0.3 | 规则形态偏向良性 |
| 直径调节 | 0.04 × min(直径−6, 25) | 对应 OR ≈ 1.04/mm，与 Brock 模型中直径系数量级一致 |
| 输出裁剪 | [1%, 99%] | 避免生成「0% 恶性」或「100% 恶性」这类不可信表述 |

这一映射的作用是把「专家评分 + 形态学征象 + 尺寸」三者融合为一个单调且可审计的数值，其参数选择依据均在代码注释中记录。它使生成语料中的概率表述有据可查，也使质检环节可以检查「低危等级是否被赋予了高恶性概率」这类逻辑矛盾（见 6.3 节）。

## 5　循证规则匹配与知识注入

规则匹配是连接「影像特征」与「临床决策知识」的桥梁，也是本研究把生成模型的不确定性收窄的关键机制。本章说明规则库的结构、匹配算法，以及规则文本如何被注入生成流程。

### 5.1　规则库结构

规则库以结构化表格形式编制（`ebm.xlsx`），共 **131 条规则**，每条规则由四个字段构成，并保留了可直接引用的原文表述：

**表 5-2  131 条规则的类别分布**

### 5.2　三层匹配算法

规则匹配按「大小 → 密度 → 风险」三层顺序执行，每一层的筛选都在前一层的候选子集内进行。这一顺序与临床医师评估结节的自然思维流程一致，也使得搜索空间逐层收窄。在具体实现上，各层的条件从规则的 IF 字段中以正则表达式抽取，再与结节状态做加权比对：

**表 5-3  三层匹配的权重与抽取方式**

| 层级 | 匹配维度 | 权重 | 抽取方式 | 取值来源 |
| --- | --- | --- | --- | --- |
| 第一层 | 结节大小 | 2（双倍权重） | 正则抽取「小于 N mm」「大于 N mm」「N–M mm」 | 直径像素值 × 像素间距换算 |
| 第二层 | 密度类型 | 1 | 关键词匹配「部分实性/混合」「非实性/磨玻璃」「实性」 | 纹理评分归并结果（表 4-4） |
| 第三层 | 风险等级 / 结节数量 | 1 / 1 | 关键词匹配「风险低/风险高」「单发/多发」 | 恶性度评分归并结果（表 4-4） |

单条规则的匹配得分为「命中权重之和 / 总检查权重」，当得分 **≥ 0.75** 时判定为匹配成功。大小维度取双倍权重，因为在 Fleischner 指南中尺寸阈值是决定管理分支的首要因素——6 mm、8 mm、15 mm 这三个阈值直接对应不同的随访策略，而同等尺寸下的密度与风险差异只改变随访间隔而非管理路径。阈值 0.75 意味着「大小必须命中，且密度或风险至少命中一项」，这既防止了大小之外的条件被忽略，也避免要求全部次要条件严格满足而导致大量结节无规则可匹配。

匹配结果经两路合并后输出：**主匹配路径**取得分最高的前 3 条规则；**规则链推导路径**根据结节特征推导关联的临床流程规则——所有结节均挂接 R-EXAM-01 与 R-EXAM-02（初始评估与基础检查），直径 > 8 mm 或（6–8 mm 且高危）时挂接 R-EXAM-03/04（分期评估），直径 > 8 mm 时挂接 R-NODULE-12/13（治疗路径评估）。两路合并后总条数上限为 8 条。这一设计使生成语料不仅包含「该结节怎么随访」，还自然延伸到「该患者接下来要做什么检查」，符合真实门诊的决策链条。

### 5.3　规则文本的知识注入

匹配结果的用途不止于给出结论，更重要的是把规则原文以可引用的形式送入生成模型的上下文。系统为每个结节产出一段规则依据文本，形如：

**代码 5-1  规则依据文本的输出格式（示例）**

```python
[R-NODULE-02] (匹配度100%) 发现单发实性肺结节，结节为6–8 mm，且肺癌风险低
[R-EXAM-01] (关联推导: 发现肺结节，需初始评估) 患者为初始就诊，且尚未完成NSCLC基础评估
[R-EXAM-02] (关联推导: 发现肺结节，需初始评估) 患者为初始就诊，且尚未完成基础实验室检查
```

这段文本被嵌入提示词，并附加硬性解码指令：要求模型在撰写临床分析与诊断意见时，必须以引用的规则条款作为推理依据，不得生成与之相悖的结论。这一机制在数据工程上的意义是**把知识约束从隐性变为显性**：医学知识原先以参数化记忆的形式存在于模型内部，不可审计；注入后变为上下文中的显性文本，可由程序逐字校验生成结果是否引用、引用是否一致。这直接为 6.3 节「循证医学验证」这一质检维度提供了可判定的比对基准。

## 6　生成语料的质量控制

从 2,424 个结节出发，系统为每个结节合成 3 套差异化患者档案，并行生成 3 份病历报告与 3 段多轮对话，产出 **7,272 条**原始生成语料。生成模型是整条链路唯一的不确定性来源，因此本章描述的环节承担着「把不确定性重新约束回可控范围」的职责。

### 6.1　生成引擎与调用层的可靠性约束

生成引擎为商业大语言模型 API，调用层内置了三级可靠性保障：**失败重试**（最多 5 次尝试，指数退避，退避因子 2；遇速率限制时首轮延迟放大 3 倍）、**流式解析**（SSE 逐块接收并拼接，避免长文本超时截断）、**空内容检测**（响应为空时视为失败并进入重试）。每次生成完成后立即落盘，避免长任务中断造成批量损失。

由于生成长任务可能因网络、配额或进程中断而部分失败，系统另设了**断点续跑机制**：扫描输出目录中已完成的记录，仅对缺失的记录重新执行生成，并通过 CSV 行号唯一标识每个待处理单元。这一机制既保证了长任务的鲁棒性，也保证了「重跑」不会产生重复样本。

### 6.2　对话结构约束与解析回退

多轮对话生成要求模型输出结构化 JSON 数组。但生成式模型输出的格式天然存在不确定性，因此解析层设置了两级策略：**首选标准 JSON 解析**（先剥离 Markdown 代码块标记，再尝试整体解析；失败则用正则定位数组片段重试）；**失败时回退到文本行解析**（按「医生：」「患者：」等前缀逐行切分角色与内容），以最大程度挽救有效文本、降低样本损失率。

解析完成后，系统对每条对话执行结构层面的即时检查。实测 429 个结节级输出的对话轮次分布为：消息数 10 条（481 例，占 88.1%）、12 条（61 例）、11 条（26 例）、8 条（15 例）、9 条（6 例）、14 条（5 例）、16 条（1 例），另有 5 例为空对话（在质检中被剔除）。即主流形态为「5 组医患问答 + 1 次病历通报」，落在 8–16 条消息的区间内。

> **【口径】口径说明。** 若按「组问答」计数，实测区间为 4–8 组，众数为 5 组；若按「消息条数」计数则为 8–16 条。论文正文以「8–15 轮」表述，指的是消息条数量级。本文档统一采用「消息条数」口径，并在第 8.5 节记录这一表述差异。

### 6.3　第一级质检：六维硬约束过滤

这是整条链路中最重要的质量闸门。系统从六个维度对每条生成语料做程序化判定，**任一维度出现 ERROR 级问题，该样本整条剔除**；WARN 级问题记录在案但不剔除。全部判据均由代码确定，无人工裁量空间。

**表 6-1  六维硬约束质检的判据**

| 质检模块 | 检查内容 | 抽查要点 |

### 6.4　第二级质检：大模型语义审核

硬约束质检能高效剔除格式缺损与逻辑串位，但无法评估自然语言的深层质量。程序可以验证对话中是否包含推理标签，却无法判断医生的口语化表述是否拟真；可以验证是否引用了规则编号，却无法判断引用的内容是否被恰当运用。为此系统在硬约束初筛之后，引入**独立于生成架构的外部大模型**执行二次审核。

审核覆盖四个维度，每个维度采用 1–5 分的 Likert 五阶量表：临床事实准确性、诊断逻辑连贯性、医患对话自然度、循证医学引用规范性。审核时同时输入原始结节特征、规则匹配结果与最终生成文本，要求模型在给出分数的同时附带简要判语。接纳边界依据医学诊断中的多准则决策方法设定：**四个维度均严格高于 4 分**方可接纳，任一项为 3 分及以下即判定为缺陷样本。

| --- | --- | --- | --- | --- | --- | --- | --- |
| 单轮病历 | 6,981 | 4.54 | 4.41 | 4.62 | 435 | 93.8% | 6,546 |
| 多轮对话 | 5,854 | 4.12 | 3.98 | — | 1,288 | 78.0% | 4,566 |

两个场景的表现差异本身就是一个有价值的数据质量观察。单轮病历是静态报告呈现，生成表现稳定，各维度均分都在 4.4 以上；多轮对话则出现明显下滑——事实准确性降至 4.12，逻辑连贯性降至 3.98，医患对话自然度仅 3.85。拦截原因集中在两类：医生角色发言流于机械模板化，患者应答出现无意义重复。这与硬约束质检中多轮场景合格率显著低于单轮的现象相互印证：**上下文长度与角色交替复杂度是生成质量的主要压力来源**。

## 7　评测数据集构建与数据隔离

评测集的构建与训练集遵循同一套清洗规则，但必须额外保证评测结果的解释力。本章说明评测集的来源、纯净子集的筛选，以及数据隔离的实际粒度与局限。

### 7.2　评测集的两种展开形式

同一条评测样本被展开为两种评测形态，分别对应两个临床场景：

**表 7-2  评测集的两种展开形式**

| 评测形态 | 展开方式 | 规模 | 对应场景 |
| --- | --- | --- | --- |
| 单轮评测 | 取 system 提示 + 患者首轮提问为输入，取第一轮病历生成为参考答案 | 722 条 | 单轮结构化病历生成 |
| 多轮评测 | 从完整对话中逐轮展开：每一轮的输入为至当前患者发言为止的全部上下文，参考答案为该轮的医生回复 | 4,411 个轮次 | 多轮医患对话推理 |

### 7.3　评测输入与参考答案的分离

为保证评测的客观性，系统在数据层面把「模型可见的输入」与「仅用于打分的参考答案」彻底分离为两类文件：

- **输入文件**（input）：只含 id 与 messages 数组，即模型实际能看到的上下文。单轮 722 条、多轮 4,411 条。
- **参考答案文件**（ground truth）：含风险等级、管理方案摘要、规则依据文本、匹配规则数与该轮的参考回复。该文件不进入模型上下文，仅供评测脚本读取。

这一分离在工程上杜绝了「参考答案泄漏进提示词」这一常见评测错误。同时，参考答案中除文本回复外还保留了结构化的规则字段，使得规则遵循类指标（Rule Recall / Rule Precision / Rule F1）可以在不依赖文本相似度的条件下独立计算。

### 7.4　数据隔离的实际粒度与已知局限

这一节记录一项必须如实说明的情况。经核验，评测集覆盖的 410 个结节中，全部 410 个都同时出现在训练集的 2,424 个结节集合中，即**结节层面重叠率为 100%**。这一事实决定了本研究评测结论的适用范围，需要明确说明：

**表 7-3  训练/评测数据隔离的实际粒度**

| 项目 | 实际情况 | 含义 |
| --- | --- | --- |
| 隔离粒度 | 样本级（患者档案 + 对话轨迹） | 训练集与评测集共享结节与影像特征，但使用不同的合成患者档案与不同的对话轨迹 |
| 评测性质 | 同分布（in-domain）评测 | 度量的是模型在**已见影像表型、未见患者背景与对话路径**条件下的表现 |
| 不构成证据 | 跨结节 / 跨患者的外部泛化 | 不能据此推断模型对新结节的泛化能力，更不能推断真实临床场景的效能 |
| 对指标的影响 | ROUGE-L 类指标可能被高估 | 同一结节的影像描述在训练中已见，文本层面的相似度会被抬升；Rule F1 受影响较小，因规则由引擎确定性匹配而非模型自由生成 |

产生这一情况的原因是工程性的：评测集与训练集出自同一次批量生成任务，按结节编号独立抽样，但未在结节层面做互斥划分。论文正文以「测试集」表述该评测集合，其含义应理解为「留出样本集」（held-out samples，即留出的是样本而非结节），而非严格意义上的独立测试集。

**改进方案。** 若需得到支持跨结节泛化结论的评测数据，应按 `patient_folder` 或结节编号做分层互斥划分：在 2,424 个结节中划出 15%–20% 作为完全不参与生成的留出结节，仅对这部分的合成语料执行评测。由于整条生成流水线为确定性可重跑（第 8 章），这一划分可以在不重新生成全部数据的前提下实现——只需对留出结节单独跑一遍生成与质检。这一改进已列入后续工作计划。

> **【引用约束】**本节内容属于对既有数据工程结果的如实复盘。在引用本研究的评测数字时，应始终带上「同分布评测、留出样本而非留出结节」这一限定，不宜将其表述为跨队列泛化性能的证明。

### 8.3　已遗失的范围与原因

经逐文件核验，唯一存在缺失的环节是**单结节生成原始件**。清洗后的 2,424 个结节中，留存的 `raw_results/`（1,452 个）与 `raw_results_v2/`（479 个）去重合并后覆盖 **1,893 个结节**，即缺失 **531 个结节**的结节级生成中间件。

缺失的原因可归结为两点：

- **实验在校园计算平台上执行，工作目录未随交付物完整打包。** 生成任务按批次推进，不同批次输出到不同的结果目录（这正是 `raw_results` 与 `raw_results_v2` 两个目录并存的原因），归档时仅取回了部分批次的目录。
- **原始 LIDC DICOM / XML 影像未纳入归档。** 这部分体量极大（数十 GB 量级），且属于公开可下载的第三方数据，未纳入项目归档属于合理取舍。

> **【影响评估】**缺失的 531 个结节级生成件，**不影响任何既有结论**。原因是：由生成件衍生出的下游产物——7,272 个 SFT 中间件、7,269 条最终训练集、4,356 条全量质检记录——全部完整留存。缺失的仅是「结节特征 → 生成结果」这一层的原始 JSON 快照，而该层可由公开数据源与留存脚本完整重建。

## 9　结论

本文档说明了本研究中训练语料与评测语料从原始标注到可用数据的完整处理过程。核心工作可归纳为四个方面：

- **构建了确定性的上游清洗链路。** 通过字段完整性校验、多标注者共识去重、特征指纹去重与恶性度分层配平四类判据，把 7,048 条带观察者间差异的原始标注记录收敛为 2,424 个标签均衡、表型多样、可直接驱动规则匹配的建模结节，并完成了临床术语标准化与类别归并。该链路已通过实际重跑验证，八项校验点全部精确命中。
- **建立了生成端的两级质量控制体系。** 第一级为六维硬约束质检，判据全部程序化、无人工裁量，负向检出率在多轮场景达 19.5%；第二级为独立外部模型执行的语义审核，以四维 Likert 严格阈值把关，拦截表层结构正确但内部语义欠佳的样本。两级串联使进入训练集的数据同时具备结构合规与语义可用性。
- **把知识约束前置到数据生成环节。** 131 条循证规则的原文被显式注入生成提示词，使生成结论具备可追溯的指南依据，并同时为质检环节提供了可逐字比对的判据。这一设计把「医学知识」从模型的隐性参数记忆转化为上下文中的显性可审计文本。
- **完成了数据留存盘点与可复现性建设。** 全部最终产物完整留存，清洗链路已验证可重放，并如实记录了 531 个结节级中间件的缺失范围、原因与重建路径，以及结节层数据隔离的实际粒度与局限。

从方法论角度看，本研究数据预处理的经验可以提炼为一条一般性原则：**当数据生产链条中引入生成模型时，质量保障的重心应从「事后清洗」转向「约束前置 + 独立校验」。** 生成模型输出的问题不像真实数据采集那样集中于噪声与缺失，而是集中于格式缺损、逻辑串位与语义偏离——这三类问题恰恰是确定性判据最擅长检出的。因此把规则知识前置注入以收窄生成空间，再用完全独立于生成架构的确定性规则与外部模型执行校验，是一条在数据规模与质量之间取得平衡的可行路径。

### B.1　清洗链路的完整复现脚本

以下脚本在留存的原始标注 CSV 上运行，可完整复现第 3、4 章的五步清洗，并输出与表 8-2 一致的校验结果。

**代码 B-1  清洗链路复现脚本（完整）**

```python
# -*- coding: utf-8 -*-
"""
LIDC-IDRI 清洗链路复现脚本
输入: lidc_nodule_features.csv  (7048 行 x 13 列)
输出: 五步过滤规模 + 恶性度分布 + 清洗后数据集
"""
import pandas as pd

FEAT = ["subtlety", "internalStructure", "calcification", "sphericity",
        "margin", "lobulation", "spiculation", "texture", "malignancy"]

raw = pd.read_csv("data/raw/lidc_nodule_features.csv")
print("S0 原始标注记录:", len(raw))                       # 7048

# ---- S1 记录级清洗: 9 项标注字段任一为空即剔除 ----
d = raw.dropna(subset=FEAT).copy()
print("S1 字段完整性校验:", len(d))                       # 7032

# ---- S2 结节级去重: 按 (xml_file, nodule_id) 取均值后四舍五入 ----
g = (d.groupby(["xml_file", "nodule_id"])[FEAT + ["diameter_pixels"]]
       .mean().round().reset_index())
g[FEAT] = g[FEAT].astype(int)
print("S2 多标注者共识去重:", len(g))                     # 6389

# ---- S3 特征指纹: 9 项整数评分按序拼接 ----
g["feature_hash"] = g[FEAT].astype(str).agg("_".join, axis=1)
print("S3 唯一特征指纹数:", g["feature_hash"].nunique())  # 2551

# ---- S4 同质化抑制: 同一指纹最多保留 3 条 ----
c3 = g.groupby("feature_hash").head(3)
print("S4 同质化抑制后:", len(c3))                        # 3816

# ---- S5 标签配平: malignancy 每级最多 500 条 ----
s = c3.groupby("malignancy", group_keys=False).head(500)
print("S5 标签配平后:", len(s))                           # 2424
print("恶性度分布:", s.malignancy.value_counts().sort_index().to_dict())
# {0: 2, 1: 446, 2: 500, 3: 500, 4: 500, 5: 476}

s.to_csv("data/processed/lidc_filtered_balanced.csv", index=False)
```

> **【实现要点】**三个不可省略的细节决定了复现的精确性：**（a）** S2 的 `round()` 必须作用在取均值之后，使评分回到整数区间，否则特征指纹的组合数会显著增多（实测变为 2,875 种）；**（b）** S3 的指纹必须在整数化之后计算，浮点评分会把每个结节变成独立组合；**（c）** S4 与 S5 的 `head(n)` 依赖 `groupby` 默认保持原行序的行为，打乱行序会改变入选样本集合（但规模不变）。

### B.3　三层规则匹配的核心逻辑

**代码 B-3  三层规则匹配的核心逻辑**

```python
def _match_xlsx_rules(self, patient_state):
    """三层匹配: 大小(权重2) -> 密度(权重1) -> 风险/数量(权重1)"""
    matched = []
    diameter_mm = patient_state["diameter_mm"]
    density     = patient_state["density"]      # 由 texture 归并
    risk        = patient_state["risk"]         # 由 malignancy 归并

    for rule in self.xlsx_rules:
        condition = rule["if_condition"]
        score, total = 0, 0

        # 第一层: 大小匹配（双倍权重，尺寸是首要分层维度）
        min_sz, max_sz = self._extract_size_range(condition)
        if min_sz is not None and max_sz is not None:
            total += 2
            if min_sz <= diameter_mm < max_sz:
                score += 2

        # 第二层: 密度匹配
        rule_density = self._extract_density(condition)
        if rule_density:
            total += 1
            if rule_density == density:
                score += 1

        # 第三层: 风险等级 / 结节数量
        rule_risk = self._extract_risk(condition)
        if rule_risk:
            total += 1
            if rule_risk == risk:
                score += 1
        rule_cnt = self._extract_nodule_count(condition)
        if rule_cnt:
            total += 1
            if rule_cnt == patient_state["nodule_count"]:
                score += 1

        # 匹配度门槛 0.75: 大小必须命中 + 至少一项次要条件命中
        if total > 0 and score / total >= 0.75:
            matched.append({"rule": rule, "match_score": score / total})

    matched.sort(key=lambda x: x["match_score"], reverse=True)
    return matched
```

### B.4　恶性概率的 logistic 映射

**代码 B-4  恶性概率的 logistic 映射实现**

```python
def _compute_malignancy_probability(features):
    """logit(p) = a*malignancy + b + sum(feature_adj);  p = sigmoid(logit)"""
    ALPHA, BETA = 1.5, -5.2
    logit = ALPHA * features.get("malignancy", 3) + BETA

    # 形态学征象调节（logit 尺度，效应量参考 Brock / Lung-RADS）
    if features.get("spiculation", 3) >= 4:   logit += 0.5   # 毛刺征阳性
    if features.get("lobulation", 3)  >= 4:   logit += 0.3   # 分叶征阳性
    if features.get("calcification", 6) in (1, 2, 3):
                                              logit -= 0.7   # 良性钙化
    if features.get("sphericity", 3)  >= 4:   logit -= 0.3   # 形态规则

    # 直径调节: >6mm 每增 1mm logit +0.04（对应 OR≈1.04/mm），增量上限 25mm
    diameter = features.get("diameter_mm", 8.0)
    if diameter > 6:
        logit += 0.04 * min(diameter - 6, 25)

    prob = 1.0 / (1.0 + math.exp(-logit))
    return round(max(0.01, min(0.99, prob)) * 100, 1)   # 裁剪到 [1%, 99%]
```
